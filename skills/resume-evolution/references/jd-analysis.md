# JD 优先分析

先读完整 JD，再看候选人对照，避免根据简历已有技能倒推岗位需求。

## 五个核心词/概念
表格：概念｜JD 原文及位置｜对应任务｜重要原因｜必需/加分/推断。
优先硬条件、核心交付、多个职责依赖的能力；不按词频排名，不让通用性格词挤占真正任务。相同含义合并，最多五项，证据不足不得凑数。
这是“岗位最重要的词”，与后续“候选人缺失的词”是两个不同列表。

## 公司寻求的技能
表格：任务｜能力｜工具/方法｜胜任证据。将工具还原成任务：SQL 可能服务于提取与汇总数据，但不能仅凭一个工具名断言完整业务职责。

## 可能解决的问题
表格：问题编号｜问题｜JD依据｜明确写出/有依据推断/无法判断｜可能交付物。
推断列入分析，不进入事实库，不当作硬要求扣分。JD 只有资格列表时允许写无法判断；不推断公司混乱、经营失败或招聘动机。

## 问题—经历证据对照
表格：问题编号｜经历与原文位置｜实际证明的能力｜直接相关/部分相关/可迁移/无证据｜不能证明什么。
直接相关=相同或高度相似任务有动作和交付证据；部分相关=仅覆盖一部分；可迁移=场景不同但方法可解释迁移；无证据=明确写暂无对应经历证据。
不要用不明确的相关性百分比，不把整个项目名称当成果证明。

## 空间价值检查
表格：原文/位置｜对本岗位的信息价值｜问题｜删除/压缩/合并/保留及理由。
关注空泛自评、重复技术栈、过长背景、无关细节。保留必要资格、联系方式和有区分度的证据。只判断对本岗位的信息贡献，不贬低经历本身；每段均有价值时明确无需删除，不凑问题。
