# 自然语言事实确认单

确认单作为独立 Markdown 文件，第一行必须逐字为：
对下列几点，分别用自然语言描述掌握你的掌握/了解程度

不得在该行之前添加标题、文件说明或评分。主回复的“第一步（共三步）”标题与文件内容分开。
其后为空行，再列本次可提升、需补证或有冲突的每一项。格式为编号、具体事项、中文冒号、换行、空白回答区。每项标签可包含简短提示，如个人动作、工具、结果和数据依据。禁止预填能力、答案、勾选框或强制等级。

一次列出全部与本次改写有关的有效待确认项，合并重复，避免泛化题库。已有明确确认不重问；用户可以写“不熟悉”“没做过”“不确定”或跳过，不要求每项都填成优势。

示例（标签必须依当前材料生成）：
```markdown
对下列几点，分别用自然语言描述掌握你的掌握/了解程度

1. SQL 多表查询与汇总（是否使用过、能独立完成什么）：


2. 订单分析项目中的个人贡献（本人负责部分、使用工具和交付结果）：


3. 报表效率提升数据（是否实际测量、原始耗时和测量方式）：


```

没有任何待确认项时仍保留首行，在下面写“暂无待补充项：”并留空行，让用户确认无补充或提出更正；不编造提升点。
用户回复后保留原文，拆为事实记录。自评“熟悉SQL”不等于有生产经验；必要时只对影响关键表述的事项补问。不把沉默、空白或“稍后填写”当认可。
用户只回复“继续”时：若明确指跳过确认，按跳过处理；若意图不清，简短确认是否按现有事实继续，不自行填答案。
